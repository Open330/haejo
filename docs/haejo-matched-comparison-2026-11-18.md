## Sol 6.2에서 차이가 줄어든 이유로 관측한 것

- **참고 문서를 한 번 더 읽었다.** Sol 6.1의 Haejo 실행은 9회 모두 명령 2개였다
  (`SKILL.md` 읽기, `haejo session … --guide --steps`). Sol 6.2는 9회 중 8회가 명령 3개로,
  그 사이에 `references/session.md`를 따로 읽었다. 실행당 전체 입력이 약 74,000에서
  약 104,000으로 늘었다.
- **한 번은 첫 Flow가 거절됐다.** Sol 6.2의 보너스 끄기 1회(8번째 쌍)에서 안전 정보 없이 보낸
  Flow가 `contract_required`로 거절됐고(화면 조작 전), 참고 문서를 더 읽은 뒤 새 작업으로 다시
  보내 61.16초, 228,701 토큰이 들었다. 결과 검증은 통과했다.
- Sky는 Sol 6.1에서 9회 모두 명령 1개와 MCP 호출 5회였고, Sol 6.2에서는 5회가 같은 형태,
  4회가 명령 없이 MCP 호출 6회였다.

이 관측만으로 입력 차이의 원인을 하나로 확정하지 않는다.

### 안내서 문구를 바꿔 본 결과

`SKILL.md`의 첫 단계 문구만 바꾼 두 판을 `--haejo-guide`로 지정해 Sol 6.2에서 각각 9쌍을 더
돌렸다(런타임은 같은 1.0.5).

| Sol 6.2, 9회 합계 | 배포된 안내서 | 판 1 | 판 2 |
|---|---:|---:|---:|
| Haejo 전체 입력 | 1,089,724 | 953,432 | 1,115,936 |
| Haejo 총 시간 | 305.67초 | 279.87초 | 300.48초 |
| `session.md`를 열지 않은 실행 | 0/9 | 2/9 | 2/9 |
| 같은 측정의 Sky 전체 입력 | 1,503,484 | 1,541,124 | 1,543,055 |

- 판 1: 첫 명령의 `--guide` 출력만으로 첫 Flow를 쓸 수 있다고 적었다.
- 판 2: 판 1에 더해 `session.md` 링크를 첫 단계에서 떼어 안내서 끝으로 옮겼다. 참고 문서를
  여러 개 찾아 읽는 실행이 늘었다(명령 5–7개인 실행이 5회).

배포된 안내서의 합계에는 위의 거절된 1회가 들어 있어, 판 1의 차이를 문구의 효과로 볼 수 없다.
두 판 모두 채택하지 않았다.

## 맞춘 조건과 검증

- 같은 Codex CLI 0.169.0, 요청 모델과 추론 강도 medium, 같은 기본 도구 설정·240초 제한·
  독립 임시 workspace·ephemeral 새 대화. Haejo 쪽은 설치된 1.0.5의 서명된 launcher와 스킬.
- 같은 소유 AppKit 앱과 작업값. arm마다 새 fixture 프로세스와 데이터 폴더로 시작했고,
  같은 쌍의 초기 상태(amount/factor/bonus/phase/control_version/active 등 10개 필드)가 일치했다.
- 실행 순서는 쌍마다 Haejo→Sky, Sky→Haejo로 교대했다. 같은 사용자 입력·포커스 보존 제한과
  소스/oracle/prior trace 읽기 금지 지시를 제공했다. 레이어별 사용 지침만 다르게 했다.
- oracle을 에이전트 밖에서 읽어 값·result·done·처리 1회를 확인했다.
- 설정 파일 hash와 source manifest가 전후 동일했다(`requested_conditions_matched: true`).
  에이전트의 지침 읽기, Flow 작성·UI 실행·최종 답까지 시간과 사용량에 포함했다.
